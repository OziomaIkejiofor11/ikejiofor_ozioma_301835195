# CHANGES — MIT 8103 portfolio for Ikejiofor Ozioma Gospel (2026/A/MIT/0976)

**Case study:** CleanRoute Waste Services (Lagos + Enugu).
**What this file is:** the student's AI drafted the five portfolios; Claude (Anthropic) then tested them in a Codespaces-like
environment (stock Ubuntu PostgreSQL 16 cluster, MongoDB 8, a non-root `codespace` user whose sudo is root-only) and fixed what
broke. The student then runs everything in their own Codespace; the evidence in the repo comes from that run.

**Honest limit of the test:** the `apt-get install` steps of `setup.sh` (PostgreSQL 16 / MongoDB 8 packages) cannot be run in the
test environment, because the servers there were already installed. The rest of `setup.sh` was checked with `bash -n`, and
`start_services.sh` was tested for the already-running case. Everything in P1–P5 was run end to end.

## Notes for the viva (left as designed, not bugs to hide)

* The pickup status trigger fires on `UPDATE` only, so an `INSERT` could create a `COLLECTED` row directly. The bulk generator and demos only insert `OPEN`.
* The truck-capacity trigger checks then inserts; two sessions inserting at the same instant could both pass. A row lock on the shift would close it.
* Customer names repeat (480 customers from 40 first × 30 surnames); the data is invented.
* The P2 indexes help Q1 clearly and the rest little. An index the planner does not use is not a win; Q4's partial index could be dropped.
* All data is invented. Nothing in this repository was measured on a machine other than the student's Codespace once they run it.
